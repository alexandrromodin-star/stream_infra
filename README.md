# Stream

Stream — персональное приложение для актёрских проб и коротких сценических дублей.

Пользователь выбирает подготовленный фрагмент фильма, играет одного персонажа перед веб-камерой, а приложение в реальном времени подставляет его лицо на лицо персонажа. Оригинальная сцена продолжает идти по исходному таймингу. Голос выбранного персонажа в фоновой дорожке удаляется или приглушается; голос пользователя и остальная сцена смешиваются для записи через OBS.

Первая версия (MVP) ориентирована на Windows и бесплатные решения с открытым исходным кодом. Технологический стек пока не утверждён: сначала проверяются подготовка сцены, live-композитинг лица, звук, задержка и передача результата в OBS.

## Текущий статус

- Тестовая машина: NVIDIA GTX 1060, 3 ГБ VRAM; простая веб-камера Logitech; OBS установлен.
- Кандидат тестовой сцены: `D:\Stream\scenes\WFWS - small part.mp4`. Его длительность, разрешение, FPS и пригодность ещё предстоит проверить.
- Исходники, маски, подготовленные аудиодорожки и манифест каждой сцены хранятся отдельно от Git в `D:\Stream\scenes`.

## Структура на диске D

```text
D:\Stream\
├── repo\                     # Git-репозиторий приложения и документации
│   ├── docs\                 # требования, архитектура, инфраструктура, план MVP
│   ├── prototypes\           # временные технические прототипы
│   ├── scripts\              # скрипты настройки и запуска
│   ├── src\                  # исходный код приложения
│   ├── .gitignore
│   └── README.md
├── scenes\                   # исходные и подготовленные медиафайлы сцен
│   └── <scene-name>\         # видео, stems, маски, таймкоды, манифест
├── models\                   # веса моделей; не коммитить в Git
├── cache\                    # кэш и временные кадры; не коммитить в Git
└── envs\                     # локальные окружения; не коммитить в Git
```

Git хранит код, документацию, сценарии подготовки и небольшие текстовые манифесты. Большие видео, аудио, модельные веса, временные файлы и записи дублей размещаются отдельно в `D:\Stream` и не входят в историю репозитория.

## Принцип разработки

Сначала проверить одну короткую сцену целиком: подготовить звук и маску, выполнить live-композитинг с веб-камерой, передать звук и видео в OBS и измерить качество, частоту кадров и задержку. После этого закрепить критерии приёмки, архитектуру и подробные задачи разработки.
