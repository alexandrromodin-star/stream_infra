# Stream — архитектура обработки лица

**Дата обзора:** 2026-10-26  
**Статус:** требование пользователя зафиксировано; конкретный движок выбирается по техническому прототипу.

## Условия

- Windows, OBS уже установлен.
- Текущая видеокарта: GTX 1060 с 3 ГБ VRAM; веб-камера Logitech.
- Входное видео сцены заранее подготовлено и идёт по исходному таймингу.
- Пользователь подтвердил, что в MVP нужны его внешность **и текущая мимика** с веб-камеры.
- Целевое окно — лицо персонажа в исходном фильмовом кадре; тело, сцена и монтаж остаются из видео.
- Пользователь подтвердил: reference-face захватывается с веб-камеры перед дублем; живая мимика идёт с камеры непрерывно; поворот головы и тело остаются из фильма.
- Голос персонажа приглушается в подготовленных таймкодах; микрофон актёра попадает в итоговый сигнал OBS.

Обычный face swap часто переносит внешность, оставляя выражение целевого лица. Это не соответствует подтверждённому требованию Stream. Нужен live reenactment: мимика с webcam управляет лицом, которое должно оставаться встроенным в меняющийся кадр фильма.

## Кандидатные схемы

### A. Reenactment по маске/треку, подготовленным для сцены — базовый кандидат

Во время подготовки сцены человек один раз задаёт целевое лицо, маску, планы и контрольные keyframes. В runtime плеер выдаёт кадр по master clock; камера даёт живую мимику; face processor анимирует/переносит её в лицо персонажа; compositor вставляет результат в исходный кадр; OBS захватывает итог.

```text
film frame + prepared face track/mask ──────┐
webcam frame -> live expression driver ──────┼-> reenactment -> composite -> OBS
background audio + user microphone ─────────┴-> synchronized mix ─────────> OBS
```

Плюс: сохраняются уникальная игра пользователя и исходное тело/фон. Риски: лицо персонажа меняет ракурс и размер при склейках; маска, освещение, перекрытия и latency могут потребовать ручных поправок и более мощной GPU.

### B. Live portrait animator с reference-face пользователя — быстрый технологический spike

Перед дублем камера захватывает нейтральный reference-face пользователя для его внешности; live-поток той же камеры остаётся driving input и переносит текущую мимику. Целевое лицо персонажа в сцене задаёт трек, маску и место композитинга, но не identity результата. Полученное лицо композитится в каждый исходный кадр. Это хороший первый тест качества/производительности на одном плане, но не доказывает работу при движении персонажа, другом ракурсе или монтажной склейке.

- **FasterLivePortrait** имеет webcam runtime с source image и driver camera. В README указаны 30+ FPS на RTX 3090; эти числа не переносятся на GTX 1060 с 3 ГБ. Веса моделей лицензируются отдельно от кода.
- **LivePortrait upstream** поддерживает портретную анимацию и portrait video editing, но его последовательная обработка видео сама по себе не подтверждает нужный realtime runtime.
- **DeepFaceLive Face Animator** — только legacy-сравнение: upstream архивирован; инструмент анимирует статичный портрет, а не фильмового персонажа с заранее подготовленной маской.

### C. Традиционный face swap — только контроль, не принимаемый результат MVP1

FaceFusion или DeepFaceLive можно проверить отдельно, чтобы измерить захват камеры, базовую нагрузку и передачу потока в OBS. Если результат сохраняет киноактёрскую мимику, он не проходит требование Stream и не заменяет схему A/B.

### D. Полностью предварительный рендер — вне текущего MVP

Оффлайн-замена лица или рендерирование живой мимики до дубля не принимает актуальную мимику пользователя в момент исполнения. Использовать только для сравнительного материала либо вернуть в обсуждение при отдельном изменении требований.

## Что известно и что нужно проверить

| Вопрос | Статус | Способ закрытия |
|---|---|---|
| Нужна ли живая мимика? | Решено: да, MVP1 | Зафиксировано в требованиях. |
| Остаются ли тело и исходное движение головы? | Решено: да | Зафиксировано пользователем для MVP1. |
| Есть ли готовая модель, которая принимает кадры динамического кино и webcam driver в реальном времени? | Не решено | Один технический spike на WFWS, измерить FPS/latency и качество paste-back. |
| Хватит ли GTX 1060 3 ГБ? | Не решено | Прототип, лог VRAM, пропуски кадров; если не проходит — сформировать требования к новой машине. |
| Какие склейки/ракурсы поддерживать в MVP1? | Не решено | Аудит WFWS; в MVP1 ограничиться одним простым планом, сложные случаи отложить. |

## Обязательный технический гейт до полной разработки

1. Агент считывает свойства `WFWS - small part.mp4`, находит один непрерывный простой план и фиксирует таймкоды.
2. Пользователь подтверждает целевого персонажа, делает reference-capture лица с камеры и оценивает желаемое качество переноса мимики.
3. На одной опорной позе проверяется webcam-driven portrait animation и композитинг лица в кадр фильма.
4. На нескольких последовательных кадрах того же плана проверяются непрерывность, маска, рот/глаза, latency, FPS и VRAM.
5. Если работает, расширить короткий spike до начала/конца плана и проверить воспроизводимость дубля.
6. Если GTX 1060 не выдерживает — подготовить минимальную конфигурацию для покупки; пользователь решает по замерам.
7. Если качество не проходит и на целевом оборудовании, показать конкретные варианты компромисса пользователю. Нельзя автоматически заменить live reenactment на обычный face swap.

## Инструменты-кандидаты

| Область | Кандидат | Роль |
|---|---|---|
| Live facial animation | FasterLivePortrait / LivePortrait | Основные кандидаты технического spike; интеграция с динамическим кино target не доказана. Проверять лицензии отдельно для кода и весов. |
| Legacy portrait animation | DeepFaceLive Face Animator | Сравнение статичного портрета с камерой; upstream архивирован. |
| Обычный face swap | FaceFusion | Benchmark камеры/выхода в OBS, не решение для обязательной живой мимики на лице фильма. |
| Ручная подготовка лица | Kdenlive Motion Tracker + Rotoscoping | Трекинг и вручную поправляемые маски/keyframes по каждому плану. |
| Подготовка звука | UVR + Audacity | Голосовой/фоновый stems и ручное удаление целевых реплик; разделение голосов персонажей не гарантируется. |
| Выход | OBS Studio | Захват окна/видеопотока и отдельного звука приложения; WebSocket добавлять только если нужен контроль записи/сцен из Stream. |
