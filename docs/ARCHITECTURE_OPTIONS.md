# Stream — варианты архитектуры и проверка инструментов

**Дата первичного обзора:** 2026-10-25  
**Статус:** варианты для проверки, окончательный стек не выбран.

## Исходные условия

- Windows, OBS уже установлен.
- Текущий тестовый компьютер: GTX 1060 с 3 ГБ VRAM, веб-камера Logitech; производительность надо измерить.
- Вход — записанная сцена. Сцена идёт по исходному таймингу.
- Пользовательское лицо приходит с веб-камеры и должно заменить лицо персонажа в кадре сцены.
- Голос персонажа удалён/подавлен, пользователь говорит через микрофон в нужные моменты; остальные голоса, музыка и эффекты сцены остаются.

## Важное различие задачи

Типовой «face swap для стрима» заменяет лицо в потоке веб-камеры. Здесь же на выходе должен остаться видеоряд фильма, а лицо нужно брать из камеры и переносить на лицо отслеживаемого персонажа в фильме. Это парная обработка двух видеопотоков и синхронизация с таймкодом сцены. Готовый режим webcam нельзя считать готовым решением всей этой задачи.

## Рассматриваемые подходы

### Вариант A — покадровая подстановка на живом воспроизведении

Плеер подаёт каждый кадр фильма как целевой кадр; видеокамера даёт актёрское лицо и мимику. Трекер знает лицо персонажа на каждом кадре, обработчик композитит лицо пользователя, а готовый кадр немедленно передаётся в OBS. Для стабильности трек лица/маски можно подготовить заранее при создании шаблона, а своп и композитинг делать во время исполнения.

**Плюсы:** сохраняется исходное видео и можно сыграть уникальную мимику в каждом дубле.  
**Риски:** основная инженерная задача; повороты, перекрытия, крупность, скачки монтажа, освещение, цвет и задержка. Нужен прототип на конкретной короткой сцене.

### Вариант B — перенос мимики/позы с камеры

Не переносить буквальные пиксели лица, а заставлять лицо персонажа повторять выражение и движение актёра. Требуется модель reenactment/face animation и отдельный композитинг в кадр.

**Плюсы:** потенциально лучше сохраняет кинематографический свет и цвет исходного кадра.  
**Риски:** сложнее интеграция и реалистичность; может требовать модели и обработки, которых нет в простом webcam-пакете.

### Вариант C — предварительно обработать сцену

До дубля обработать весь фильмовый клип, заменив лицо выбранного персонажа постоянным цифровым лицом, затем во время дубля захватывать актёра отдельным слоем или использовать заранее полученную замену.

**Плюсы:** легче добиться ровной картинки и снять вычислительную нагрузку с live-части.  
**Риски:** статичная замена не отражает мимику актёра; отдельный live-слой может выглядеть как наклейка. Подходит как контрольный визуальный прототип, но не равно требуемой живой игре.

### Вариант D — классический live face swap как тестовый эталон

FaceFusion документирует webcam-режим: inline внутри UI и UDP-выход `udp://localhost:27000`, который можно захватить в OBS. Это полезно для быстрого теста производительности GTX 1060 и схемы передачи камеры, но документация описывает webcam feed, поэтому потребуется доказать, можно ли использовать его процессор внутри архитектуры «видеокадр сцены + live-камера», а не считать его интеграцию решённой.

DeepFaceLive описывает live face swap для стримов и видеозвонков, но репозиторий архивирован 13 ноября 2024 года; опубликованные требования рекомендуют RTX 2070 или выше. Рассматривать только как исторический/контрольный прототип, не как основу нового проекта.

## Рекомендуемое направление MVP

Не выбирать вариант только по описанию продукта. Сделать короткий технический прототип на 10–20 секундах одной сцены с крупным планом и относительно фронтальным лицом:

1. Измерить камеру, модель GPU, объём VRAM, FPS и задержку на текущей GTX 1060.
2. Отдельно проверить FaceFusion webcam UDP с OBS как эталон live-обработки камеры.
3. Проверить ключевой риск: подачу кадров фильма как целевых кадров вместе с live-камерой и композитинг обратно в исходный видеоряд.
4. Сравнить live face swap с переносом мимики/композитингом по одному набору критериев: стабильность трека, мимика, профиль, резкие монтажные склейки, артефакты, FPS, задержка.
5. На основании результата определить, что оставить live, а что подготовить заранее в шаблоне.

GTX 1060 с 3 ГБ VRAM — ограниченная тестовая конфигурация для нейросетевых моделей и одновременного live-воспроизведения. Нельзя обещать конкретную частоту кадров до замера. Проверка на текущем компьютере даст нижнюю отправную точку; целевую конфигурацию нового компьютера определять по результату прототипа.

## Предварительная схема данных

```text
Подготовка шаблона
  исходный клип -> таймкоды/кадры/треки лица
  исходная аудиодорожка -> разделённые stems -> ручная коррекция при необходимости
  параметры сцены -> scene.json

Исполнение
  видео сцены ───────────────┐
  live webcam -> лицо/мимика ├-> композитинг -> выход видео -> OBS
  фоновые аудиостемы ────────┤
  микрофон актёра ────────────┴-> синхронный микс -> OBS
```

`scene.json` должен хранить относительные пути к файлам, частоту кадров, размеры, таймкоды реплик, синхронизационные смещения, идентификаторы выбранных потоков и версии параметров обработки. Исходники и рендеры сцены не должны зависеть от абсолютного пути, чтобы переносить набор между папками на диске D.

## Инструменты-кандидаты, не утверждённый стек

| Область | Кандидат | Роль в проверке / ограничение |
|---|---|---|
| Live face processing | FaceFusion | Webcam inline/UDP в OBS; проверить парную обработку фильмового кадра и live-камеры. Кодовая лицензия OpenRAIL-AS; до выбора проверить условия и лицензию конкретных весов отдельно. |
| Live face processing | DeepFaceLive | Исторический контрольный вариант; архивирован в 2024 году и рекомендовал существенно более мощную GPU. |
| Захват и монтаж медиа | FFmpeg | Прототипы декодирования, кадров и аудиостемов; финальную упаковку выбрать после теста синхронизации. |
| OBS | OBS Studio | Приём видеоряда/аудио, запись дубля; webcam guide описывает виртуальную камеру для раздачи сцены OBS наружу. |
| Управление OBS | obs-websocket | Встроен в OBS 28+; подключать, если потребуется запускать запись, выбирать сцену или показывать статус из Stream. |
| Захват звука приложения | Application Audio Capture в OBS | Может захватывать звук отдельного приложения в Windows 10 (2004+) / Windows 11; проверит отдельное аудио-маршрутизирование без обязательного виртуального кабеля. |

Лицензии моделей, весов, обучающих наборов и самих программ проверяются отдельно перед включением в MVP. Наличие открытого репозитория не означает, что каждый загружаемый модельный файл имеет ту же лицензию.
