# Stream — стартовая инфраструктура

**Статус:** базовые каталоги и пустой локальный Git-репозиторий созданы на D:; рабочий код пока не добавлен.

## Размещение на диске D

Предлагаемая структура:

```text
D:\Stream\
  repo\                  # локальный Git-репозиторий
    docs\                # требования, архитектура, план реализации
    src\                 # код приложения
    prototypes\          # короткие проверочные прототипы
    scripts\             # setup/run утилиты
    .gitignore
  scenes\                # медиаданные, вне Git
    <scene-id>\
      source\            # пользовательские исходники
      prepared\          # обработанные аудиостемы, трекинг и scene.json
      takes\              # локальные дубли, если они не управляются OBS
  models\                # скачанные веса; вне Git
  cache\                 # временные кадры, кэши и промежуточный рендер; вне Git
  envs\                  # большие/локальные runtime-окружения; вне Git
```

На диске D обнаружено около 205 GiB свободного места. Это достаточно для старта и нескольких коротких сцен; исходные фильмы, рендеры и записи быстро расходуют место, поэтому перед масштабированием проверить размер библиотеки.

## Git

- Git установлен у пользователя; отдельную установку Git не выполняли.
- Один локальный Git-репозиторий инициализирован в `D:\Stream\repo`.
- Git хранит исходный код, документацию, скрипты, конфигурацию примера и схему `scene.json`.
- Git не хранит большие видео, аудио, webcam-записи, весы моделей, временные кадры, логи и виртуальные окружения. Для этого в `.gitignore` будут правила по путям `D:\Stream\scenes`, `models`, `cache` и `envs`.
- На первом этапе репозиторий локальный; удалённый сервер/облако не требуется. Позже можно добавить приватный remote, если понадобится резервная копия или работа с другого устройства.
- Резервная копия медиатеки — отдельная задача: Git не заменяет её.

## Среда разработки

- Разрабатывать приложение в первую очередь для Windows, так как это текущая среда пользователя и целевой сценарий с OBS.
- Для проб использовать изолированное окружение; зависимости и версии фиксировать в lock-файле/манифесте проекта.
- Не устанавливать случайные глобальные Python/ML-пакеты в систему. Точную версию Python, PyTorch/ONNX Runtime, CUDA runtime и способ упаковки выбрать после проверки выбранного face-processing кандидата.
- Модели скачивать в `D:\Stream\models`; кэш и временные файлы направить на диск D, чтобы не заполнять системный диск.
- Версии OBS, драйвера NVIDIA, FFmpeg и модели GPU записать в протоколе теста.

## Предлагаемый порядок запуска инфраструктуры

1. Добавить стартовый коммит с документацией, `.gitignore` и README; проверить статус, чтобы медиаданные не попали в отслеживание.
2. Снять инвентаризацию Windows, OBS и веб-камеры; текущая GPU известна: GTX 1060 с 3 ГБ VRAM.
3. Подготовить изолированное окружение для небольшого прототипа выбранного live-движка.
4. Сохранить тестовые результаты (версии, FPS, задержка, артефакты), а затем утвердить стек MVP.

## Граница между проектом и сценами

Код и инструкции меняются через Git. Каждая сцена — отдельная папка данных с оригиналом, подготовленными компонентами и манифестом. Сцена должна ссылаться на файлы относительными путями. Это позволит перемещать библиотеку сцен и делать резервные копии без переписывания Git-истории и без включения видео в коммиты.
